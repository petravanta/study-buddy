# Notes for coding agents

Follow the shared standards in https://github.com/petravanta/general/blob/main/STANDARDS.md (hub link, theme switch, shared look, built-in knowledge, user data). Take patterns from there, not from the other apps. This file only adds what's specific to Study Buddy.

- The app is `index.html` with no build step. Serve the folder (`python3 -m http.server`) to run it; built-in sets load with `fetch()`. The shared look, `google-token.js` and `drive-store.js` are inlined between their marker comments.
- Built-in knowledge is question sets, one file per set: `data/sets/<id>.json`, listed in display order in `data/sets.json`, all covered by `data/schema/sets.schema.json`. `loadBuiltin()` puts them in `BUILTIN`. A user's own sets are records in `doc.sets` with the same shape (plus `u`); `setById()` looks in the user's sets first, then `BUILTIN`. Every new built-in set file also goes in `APP_SHELL` in `sw.js`.
- The document (`studyBuddy.data` in `localStorage`, and `Study Buddy data.json` in Drive through `DriveStore`) follows the standards' *User data* shape, version 1, with these lists:
  - `programmes`: `{ name, exam (YYYY-MM-DD or ''), sets: [set ids], archived, quick: { count, pick, answer } }`. `quick` is the flashcard settings.
  - `sets`: the user's own sets, `{ name, description, source?, questions: [...], tests?: [...] }`. Questions are nested, so a set merges as one record.
  - `testTypes`: practice tests a programme defines, `{ p (programme id), order, name, count (0 = all), pass (percent), pick, answer, feedback, stopEarly, timeLimit (minutes), tags, why? }`. The same fields (without `p` and `order`) are a set's suggested `tests`; `linkSet()` copies those into a programme when the set is added.
  - `tests`: finished practice tests, `{ p, type, name, at, end, total, asked, right, pass, passed, stopped, timeUp }`.
  - `attempts`: one per answer, `{ s (set id), q (question id), ok, at, p, m (answer mode), t? (test id), g? (what was typed or picked) }`. History belongs to the question (`s/q`), not the programme, so it carries across programmes that share a set. Attempts are never deleted by the app; removing a test result or a programme leaves them.
  - `personal`: a person's own answers to questions marked `personal` in a set (their Senators, their state capital), `{ id: '<set id>/<question id>', answers: [...] }`. The id is the question's key, so it is the same on every device.
  Which programme is open (`studyBuddy.current`) and which tab (`studyBuddy.tab`) are per device, outside the document.
- `pool()` swaps a personal question's answers for the person's own and marks it `blank` until they have filled it in. Rounds leave blank questions out; `startRun()` first opens `fillDrawer()` for any blank ones in its pool, unless the person chose *Not now* this session (`skipFill`). Shared exports carry `personal` (what to ask) but never the person's answers.
- `qstat(key)` is the one place that decides how well a question is known: its attempts, right count, the current right streak, and a level (`new`, `learning` = missed last time, `getting` = streak 1, `confident` = 2–3, `mastered` = 4+). `order()` turns a test's `pick` into a question order from those levels. `hist()` indexes attempts by `s/q` and is rebuilt when `rev` changes (every `save()`).
- A round (`run`) holds its questions, the phase (`ask`, `reveal` for flip-and-mark, `feedback`) and the config. `record()` saves each answer as an attempt straight away, so quitting midway keeps what was answered. `finish()` writes the `tests` record. With `stopEarly`, `next()` ends the test once `right >= needed()` or a pass is out of reach.
- `checkTyped()` marks typed answers: `core()` lowercases and drops punctuation, accents and small words, words in (brackets) are optional, numbers must match exactly, and three quarters of an answer's words (each allowing a typo per four letters) must be there. Questions with `need > 1` split the input on commas, semicolons and "and".
- Import (`#fileIn`) takes a backup (merged with `mergeDocs()`), a set file (`{ format: 'study-buddy-set', formatVersion: 1, set }`, a bare set or an array of questions), or CSV / tab-separated text through `parseTable()`, whose header names are in `COLS`. `cleanQuestion()` and `cleanTest()` are the only way imported data becomes records. `shareSet()` writes the share format, with only schema fields and no attempts.
